# Руководство пользователя Solarman Hub

**Solarman Hub — независимый любительский проект. Он не связан с SOFAR (SofarSolar).**

Это руководство поможет настроить Hub, подключить логгер и при необходимости использовать ESP32 Companion. Выбор языка в Hub меняет язык панели и руководства. У Companion собственный англоязычный интерфейс.

## [hub] Использование Hub

Войдите с паролем вебпанели или токеном администратора. Панель показывает измерения и состояние логгера, облака, MQTT и локального хранилища. Проверяйте и соединение логгера, и время последнего измерения: подключённый логгер мог ещё не отправить отчёт.

Измените язык рядом с индикатором обновления. Браузер запомнит ваш выбор.

В **Обзоре** выберите логгер и **Последнее измерение** или **История**. Исторические образцы сохраняют исходные названия полей, единицы и версию профиля. Нажмите название измерения, чтобы открыть временной график. Выберите диапазон времени, перемещайте указатель по графику или управляйте ползунком точек с клавиатуры. Перерывы приёма разрывают линию; уменьшение числа точек сохраняет минимумы и максимумы.

В **Настройках** сначала сохраните изменения, затем выберите **Применить и переподключить**. Текущие сеансы закроются, чтобы логгеры подключились с новыми настройками. Изменение адреса или порта прослушивания также требует перезапуска Hub и соответствующего сопоставления портов Docker.

**Устройства** различают значения, обнаруженные в кадрах, и производителя с моделью, указанными в выбранном профиле. Отсутствующие сведения обозначаются как необнаруженные. Настроенная модель не доказывает автоматического определения оборудования.

## [install] Установка и первое подключение

**Автоматическая установка VM**

Выполните эту команду как **root в Shell узла Proxmox**, а не внутри VM. Мастер проведёт вас по шагам. Перед подтверждением проверьте сводку.

```sh
bash -c "$(wget -qLO - https://raw.githubusercontent.com/ordigital/solarman-hub/main/scripts/proxmox-vm.sh)"
```

Введите адрес IPv4 с маской (например `192.168.1.50/24` или `192.168.1.50/255.255.255.0`) либо оставьте поле пустым для DHCP. Шлюз и DNS запрашиваются только для статического адреса.

Мастер спросит свободный ID VM, имя, хранилище диска, хранилище типа каталог для Cloud-Init snippets, сетевой мост/VLAN, DHCP или статический IPv4 (адрес/префикс, шлюз и DNS), ресурсы, необязательный файл открытого SSH-ключа и пароль вебпанели не короче 8 символов. По умолчанию: Debian 13, 2 vCPU, 2 ГБ RAM и диск 20 ГБ. Он проверит SHA-512 официального образа и установит Docker и существующий проект Compose в новой VM. При необходимости добавит тип содержимого snippets в хранилище, сохранив остальные типы. Существующие VM не изменяются.

Используйте Docker Compose. В Proxmox простым решением будет небольшая виртуальная машина Debian с Docker; не устанавливайте приложение непосредственно на гипервизор. Приложение также работает с Python 3.12 или новее.

В каталоге репозитория:

```sh
docker compose up -d --build
docker compose exec hub solarman-hub token --data-dir /data
```

Откройте `http://SERVER_IP:8080`. Токен хранится в `/data/admin-token.txt` и не меняется после перезапуска или обновления. Новый создаётся только при отсутствии файла, например в пустом томе данных. Стандартный опубликованный порт логгера — `10000/TCP`. Если используется существующий контейнер, запущенный через `docker run`, Compose им не управляет: используйте его фактическое имя, например:

```sh
docker exec solarman-hub solarman-hub token --data-dir /data
```

Альтернативное сопоставление портов хоста предотвращает конфликты:

```sh
HUB_LOGGER_PORT=18899 HUB_WEB_PORT=18080 docker compose up -d --build
```

Добавьте числовой **серийный номер логгера**, а не инвертора. При необходимости ограничьте IP источника и зарезервируйте его в DHCP. Выберите совместимый профиль декодирования, сохраните и примените. Новая установка не принимает неизвестные серийные номера логгеров. В настройках удалённого TCP-сервера логгера укажите IP хоста Hub и опубликованный порт логгера. Подробные шаги приведены ниже в разделе «Перенаправление собственного логгера: локальный сервер V5».

Для работы без Docker:

```sh
python3 -m venv .venv
.venv/bin/pip install .
.venv/bin/solarman-hub serve --data-dir ./data
# In a second terminal:
.venv/bin/solarman-hub token --data-dir ./data
```

Для постоянной установки Python используйте менеджер процессов. `solarman-hub check-config --data-dir ./data` проверяет конфигурацию и ссылки на профили.

## [cloud] Пересылка в облако, локальные ACK и MQTT

Стандартный адрес облака — `access3.solarmanpv.com:10000`. Hub пересылает исходные байты V5 и ответы облака. Ему не нужны пароль учётной записи Solarman, cookies или пароль Wi-Fi. Кадры по-прежнему содержат идентификаторы устройств и метаданные протокола; это частные данные установки.

ACK сообщает логгеру, что отчёт получен. Для поддерживаемых отчётов Hub отправляет облачный ACK или, если соединение с облаком не удалось либо истекло время ожидания, один локальный ACK. Затем он закрывает неудачный облачный сеанс и игнорирует запоздавшие ACK. Неизвестные действительные кадры могут проходить дальше, но не получают локальный ACK. Трафик движется в обе стороны, включая команды из облака производителя.

Если Интернет недоступен, но LAN работает, локальные показания и MQTT могут продолжать работу. **Отчёты, подтверждённые локально во время сбоя, не загружаются в облако автоматически позже. Облачная история может иметь пропуски.** Остановка Hub прерывает настроенный путь пересылки. Возвращаясь к прямому облачному сервису, восстановите исходные адреса назначения логгера.

Для Home Assistant подключите оба приложения к одному MQTT-брокеру. В Hub укажите хост и порт брокера, необязательные имя и пароль и настройки TLS; включите MQTT Discovery. В HA настройте официальную интеграцию MQTT. Токен API HA не нужен. Проверка брокера проверяет соединение и аутентификацию, а не ACL публикации.

Discovery появляется после первого совместимого образца. Стабильные идентификаторы датчиков используют серийный номер логгера и ID поля. Доступность MQTT, возраст последнего показания логгера и соединение с облаком отслеживаются отдельно. Самостоятельно выберите подходящие счётчики энергии на панели энергии HA. Смена брокера или префикса тем может потребовать удаления устаревших сохранённых тем Discovery на старом брокере.

## [history] История, графики и хранение

История измерений хранится в `/data/history.sqlite3`. Проблемы хранилища не останавливают пересылку в облако. Старые архивы измерений JSONL импортируются один раз в фоновом режиме, пока продолжают поступать новые отчёты. Ход импорта и ошибки хранилища проверяйте в **Конфигурации**.

Установите **Хранение истории** в днях и **Ограничение размера истории** в МБ. Действуют оба ограничения; первое достигнутое удаляет самые старые данные. Возраст определяется временем получения, поэтому неверные часы инвертора не сохранят данные навсегда. Ноль дней отключает только ограничение возраста. Отключение истории прекращает новые записи, но не удаляет сохранённую историю.

Ограничение размера включает базу, её журналы и резерв для обслуживания. Временные записи могут ненадолго его превышать, поэтому оставляйте свободное место на диске. Необработанные кадры, архивы JSONL и журналы событий имеют отдельные ограничения. **Уменьшение лимита истории удаляет старые данные.** Сначала создайте копию данных, которые хотите сохранить.

Графики используют время образца, если оно доступно, иначе время получения. Разные версии профилей не позволяют объединять несовместимые масштабы или единицы. Для больших диапазонов возвращается не более 1500 выбранных точек; при превышении лимита сканирования сузьте диапазон. Образцы вне порядка могут появиться в истории, не заменяя новейшие текущие данные. Повторные образцы сохраняются только один раз.

## [devices] Сведения об устройствах и профили декодирования

Hub наблюдает серийный номер логгера и IP узла из сеанса V5/TCP. Проверенные форматы рукопожатия LSW3 могут показывать прошивку; поддерживаемый отчёт Sofar HYD содержит серийный номер инвертора. Для каждого декодированного значения указаны источник и время наблюдения. Hub не определяет MAC-адрес из TCP-соединения и не угадывает произвольные текстовые поля.

Встроенный профиль Sofar HYD G3 декодирует 48 полей из отчёта длиной 2115 байт, проверенного на установке HYD 15KTL-3PH/LSW3. Другое оборудование требует независимой проверки. Одного соответствия кода и длины недостаточно для доказательства семантической совместимости.

Профили хранятся в формате JSON и содержат: код, длина полного кадра, сопоставление времени и поля. Смещение ноль — первый байт `A5` полного кадра V5. Поля задают смещение, ширину, порядок байтов, знаковость, масштаб, единицу и необязательные классы HA. Ссылка на регистр — примечание, а не команда опроса.

Клонируйте встроенные профили для редактирования. Прежде чем назначить карту, используйте просмотр HEX и сравните несколько образцов с независимыми показаниями. Другой формат V5 может потребовать только профиля; другой протокол передачи требует кода. **Только пересылка** передаёт данные без декодирования.

На странице профилей импортируйте отдельный профиль JSON или пакет ESP32. Проверьте сводку, состояние проверки и конфликты. Импорт сохраняет профиль и, где уместно, новую запись логгера; он не применяет изменения и не перенастраивает логгер. Черновики сырых слов явно не проверены и не имеют выдуманных единиц или энергетических классов.

## [spoofing] Перенаправление собственного логгера: локальный сервер V5

Чтобы получать отчёты локально, измените удалённый сервер логгера на Hub или Companion. В этом руководстве «спуфинг» означает использование локального сервера вместо облачного.

Для обычной работы:

```text
Logger → Hub → manufacturer cloud
             ↘ local history and MQTT
```

Для временного анализа:

```text
Logger → ESP32 Companion → Hub → manufacturer cloud
```

### Изменение удалённого сервера логгера

Эти шаги предназначены для логгера LSW3 со скрытой страницей настроек сервера. Названия меню и поведение после перезапуска могут зависеть от прошивки.

1. **Найдите оба адреса.** В списке клиентов DHCP маршрутизатора найдите IP-адреса LAN логгера и сервера Hub. Например, логгер может иметь `192.168.100.205`, а Hub — `192.168.100.50`; замените примеры своими адресами. Зарезервируйте оба. Адрес логгера открывает его настройки, а на адрес Hub будут отправляться отчёты. В Proxmox используйте адрес VM Debian для Hub.
2. **Сначала подготовьте Hub.** В **Настройках** добавьте числовой серийный номер логгера, выберите совместимый профиль, сохраните и выберите **Применить и переподключить**. Если хотите сохранить передачу в облако, включите пересылку, используя исходный облачный адрес логгера. Проверьте порт логгера, опубликованный Docker; стандартный — `10000/TCP`.
3. **Откройте настройки самого логгера.** В браузере в той же LAN откройте `http://LOGGER_IP/config_hide.html`, заменив `LOGGER_IP` адресом логгера. Войдите с учётными данными администратора логгера, а не учётной записью Solarman или токеном Hub. На проверенном логгере заводские имя пользователя и пароль — `admin` / `admin`. Если они не подходят, проверьте наклейку или инструкцию либо обратитесь к установщику; если пароль меняли, используйте текущий. Скрытая форма загружается внутри этой страницы; если открыть `hide_set_edit.html` напрямую, настройки могут не загрузиться или не сохраниться.
4. **Сохраните копию обеих конфигураций серверов.** Перед изменениями запишите все значения в **Server A Setting** и **Optional Server Setting(B)**, включая IP-адрес, доменное имя, порт и тип соединения. Помогут снимки экрана. Сохраните эти данные для восстановления прямой передачи в облако.
5. **Настройте основной адрес.** В **Server A Setting** введите IP-адрес LAN Hub в **IP address**, очистите **Domain name**, введите опубликованный порт логгера Hub в **Port** и выберите **TCP** в **Connection**. Обычно это делает Hub адресом A. Используйте порт логгера, а не порт веб-панели `8080`, порт `8899` или частный IP контейнера Docker. Сначала не меняйте B, если прошивка не требует резервного варианта ниже.
6. **Сохраните каждую изменённую форму.** A и B имеют отдельные кнопки **Save**. Сохраните A, а если меняли B — сохраните и его отдельно. Снова откройте настройки и проверьте сохранённые значения.
7. **Перезапустите логгер.** Сначала воспользуйтесь его функцией перезапуска. Некоторые прошивки сохраняют старый TCP-сеанс даже после запроса из панели. Если логгер продолжает отправлять данные по старому адресу, физически перезапустите только логгер и только тогда, когда его инструкция разрешает сделать это безопасно. Не меняйте рабочие настройки инвертора и не отсоединяйте его кабели питания.
8. **Проверьте фактические отчёты.** В Hub убедитесь, что логгер подключился, новые измерения имеют актуальное время и продолжают обновляться. Одного соединения недостаточно. Если пересылка в облако включена, проверьте, получает ли Hub облачные подтверждения (ACK), а затем — появляются ли новые показания на облачной странице производителя. Подождите обычный интервал отправки логгера.

### Если вашему LSW3 нужен резервный сервер B

На проверенной прошивке LSW3 установка только A на Hub не обеспечивала надёжную отправку. Работала следующая настройка:

| Настройка | Сервер A | Сервер B |
|---|---|---|
| IP address | IP-адрес LAN Hub | IP-адрес LAN Hub |
| Domain name | Пусто | Пусто |
| Port | `10001`, без службы, прослушивающей этот порт | Опубликованный порт логгера Hub, обычно `10000` |
| Connection | TCP | TCP |

A намеренно направлен на закрытый локальный порт, чтобы логгер перешёл на B. **B — резервный адрес, а не вторая одновременная копия каждого отчёта.** Убедитесь, что выбранный порт A никто не прослушивает. Сохраните обе формы отдельно, перезапустите логгер и повторите проверку измерений и облака. Такое поведение относится к проверенной прошивке; используйте его, если обычная настройка A не работает.

### Возврат к прямой передаче в облако

Восстановите все исходные настройки A и B, включая доменные имена, порты и типы соединений. Сохраните каждую форму и перезапустите только логгер. Прежде чем останавливать Hub, проверьте новые измерения в облаке производителя. Отчёты, локально подтверждённые во время перерыва, позже не загрузятся в облачную историю.

### Companion между логгером и Hub

Включите на Companion ровно одно соединение с сервером: Hub или облаком. Не пытайтесь дублировать отчёт в оба. Если используется Hub, сначала разрешите серийный номер логгера и используйте опубликованный TCP-порт Hub. Тайм-аут подключения Companion составляет 3 секунды. Настраиваемый тайм-аут ACK по умолчанию — 30 секунд (10–120 секунд); с Hub он должен быть больше полного времени подключения, инициализации и ожидания ACK в Hub. Без сервера Companion локально подтверждает известные кадры; в облако они не доставляются.

Для локальных ACK нужно правильное время. Обычно его предоставляет NTP; открытие интерфейса Companion также передаёт время браузера, если часы ещё не настроены. Пока времени нет, Companion не подтверждает отчёт, чтобы логгер мог повторить попытку.

## [esp32] Прошивка и настройка ESP32 Companion

Предоставленная сборка предназначена для **классического ESP32 с 4 МБ flash**, проверенного на семействе ESP32-D0WD-V3. Это не образ для ESP32-C3, S2 или S3. Питайте плату разработки через USB; она общается через Wi-Fi.

Готовые образы и контрольные суммы находятся в `firmware/esp32-companion/dist/`:

- `factory.bin`: первая установка через USB с загрузчиком и таблицей разделов;
- `firmware.bin`: образ только приложения для OTA;
- `SHA256SUMS`: хеши целостности.

Используйте USB-кабель, передающий данные. Установите средство прошивки в виртуальной среде и определите правильный порт:

```sh
python3 -m venv .esp-tools
.esp-tools/bin/pip install esptool==5.6.0
.esp-tools/bin/python -m esptool --port /dev/ttyUSB0 flash-id
sha256sum -c firmware/esp32-companion/dist/SHA256SUMS
.esp-tools/bin/python -m esptool --chip esp32 --port /dev/ttyUSB0 write-flash 0x0 firmware/esp32-companion/dist/factory.bin
```

Для доступа к последовательному порту может понадобиться членство в системной группе доступа. Закройте мониторы порта перед прошивкой. Если автоматический вход в загрузчик не удался, удерживайте BOOT при запуске инструмента и отпустите после подключения. Заводская прошивка может сбросить сохранённые настройки; OTA их сохраняет.

Также на **хосте Linux с Docker Engine** можно прошить устройство напрямую из одноразового контейнера. Клонируйте или скачайте этот репозиторий и выполните команды из его корневого каталога. Закройте мониторы последовательного порта, подключите ESP32 к этому хосту Docker и определите его последовательное устройство; `/dev/ttyUSB0` — пример:

```sh
ls -l /dev/serial/by-id/
ESP_PORT=/dev/ttyUSB0 docker compose --profile tools run --rm --build esp-flash flash-id
ESP_PORT=/dev/ttyUSB0 docker compose --profile tools run --rm esp-flash
```

Первая команда собирает инструмент и проверяет подключённый чип без записи. Вторая проверяет контрольную сумму прилагаемого образа и записывает `factory.bin` по адресу `0x0`. Замените `ESP_PORT` путём платы `/dev/ttyUSB…`, `/dev/ttyACM…` или `/dev/serial/by-id/…`. Инструмент не требует Python на хосте и работает отдельно от Hub. Для последующих обновлений используйте OTA, чтобы сохранить настройки.

USB должен быть доступен **на машине, где работает демон Docker**, а не только на компьютере с веб-панелью. В виртуальной машине Proxmox сначала передайте ей USB-устройство. Эта команда предназначена для Docker Engine в Linux; Docker Desktop в Windows/macOS по умолчанию не предоставляет последовательные устройства таким способом. В этих системах используйте приведённые выше нативные инструкции esptool или явно настройте передачу USB.

На странице **ESP32 / Прошивка** Hub после входа также доступны загрузки **Прошивка для первой установки через USB**, **Прошивка для обновления OTA** и **Контрольные суммы SHA-256**. Веб-панель скачивает файлы; она не прошивает устройство через USB-порт компьютера с браузером.

Читайте последовательный вывод USB со скоростью **115200 baud**. При запуске выводятся уникальные SSID и пароль настройки, а также имя администратора `admin` с уникальным паролем. Подключитесь к точке доступа настройки и откройте `http://192.168.4.1`. Введите учётные данные администратора в окне браузера. Настройте домашние SSID и пароль и сохраните. Плата перезапустится; найдите её IP в LAN через вывод USB или DHCP либо попробуйте `http://solarman-companion.local`.

Режим приёмника слушает `10000/TCP`. Укажите разрешённый серийный номер логгера, при необходимости выберите сервер и направьте логгер на IP ESP32. Приёмник поддерживает один активный логгер, четыре сообщения в очереди и кадры до 4096 байт. Буфер кадров, отчёт и пассивный захват находятся в RAM и теряются после перезапуска.

Для сборки из исходников используйте PlatformIO с `firmware/esp32-companion/platformio.ini`.

## [export] Экспорт профилей, настроек и захватов

В **Profile builder and exports** Companion получите отчёт, затем загрузите известную карту HYD, непроверенный черновик сырых слов или сохранённый собственный профиль. Черновик показывает до 64 сырых слов; определите значение, порядок байтов и масштаб, сравнивая несколько образцов и независимые измерения. Прошивка не может автоматически определить электрический смысл зашифрованных пакетов или произвольных байтов.

Отредактируйте JSON и сохраните собственный профиль на плате или скачайте профиль напрямую. Хранилище собственного профиля ограничено 12 KiB и 128 полями. Скачайте пакет импорта Hub, чтобы включить предлагаемую запись логгера и состояние проверки. Добавление сырого образца необязательно, поскольку он раскрывает идентификаторы устройств. Импортируйте файл в Hub, проверьте и сохраните, а когда будете готовы — явно примените настройки.

**Download ESP32 settings (without passwords)** экспортирует имена сетей, режим и параметры захвата и соединения с сервером. Пароли Wi-Fi и администратора не включены. Сохраняйте файл как справку конфигурации; повторно введите секреты при восстановлении на очищенной плате. OTA сохраняет настройки NVS и профиль во flash.

В пассивном режиме настройте MAC логгера и BSSID целевой точки доступа. Привязка ESP32 к точке доступа логгера помогает в mesh-сетях: его единственный радиомодуль 2,4 ГГц захватывает канал станции и точки доступа. Классический ESP32 не захватывает радиоканал 5 ГГц. Если логгер перейдёт к другой точке, обновите целевую точку или захватывайте новый канал.

Скачанный PCAP содержит ограниченный снимок примерно 32 KiB; самые старые пакеты перезаписываются, а потери очереди подсчитываются. Часто сохраняйте данные во время анализа, особенно при переподключении логгера. Защищённые кадры Wi-Fi остаются зашифрованными. Расшифровка WPA2 на компьютере обычно требует правильного ключа Wi-Fi и подходящего захваченного рукопожатия; для WPA3 это не гарантируется. Используйте Wireshark и храните захват конфиденциально. См. [руководство Wireshark по расшифровке](https://wiki.wireshark.org/HowToDecrypt802.11).

## [ota] Обновления OTA и восстановление

Скачайте подходящий `firmware.bin` Companion, проверьте его хеш и откройте **Firmware update (OTA)**. При стабильном питании загрузите один образ приложения. Не загружайте `factory.bin` через OTA. Средство обновления проверяет вход и данные образа о чипе и продукте и активирует новый образ только после завершения загрузки.

Во время загрузки захват и пересылка приостанавливаются, поэтому логгер может переподключиться. Неудачная или прерванная загрузка сохраняет текущее приложение и возобновляет работу. Успешная загрузка перезапускает ESP32. Если новое приложение не запускается, прошивка автоматически не возвращается к предыдущей версии. Восстановите плату через BOOT/USB и заводской образ.

OTA использует HTTP со входом администратора. Образы прошивки не подписаны криптографически, поэтому используйте проверенные файлы и обновляйте только в доверенной LAN. Любой, кто знает пароль администратора, может установить прошивку. Храните пароль и экспортированные захваты конфиденциально.

## [operations] Резервное копирование, устранение неполадок и ограничения

Чтобы задать или изменить пароль вебпанели, выполните эти команды в каталоге проекта Compose. Используйте не менее 8 символов. Hub хранит хеш с солью в `/data/admin-password.json`, а не сам пароль. Перезапуск активирует изменение и закрывает текущие вебсеансы. Токен администратора остаётся действительным для восстановления доступа и API.

```sh
docker compose exec hub solarman-hub password --data-dir /data
docker compose restart hub
```

При остановленной службе создайте копию всего тома Hub `/data`, включая SQLite, конфигурацию, профили, токен и архивы. Для смонтированных каталогов сохраните UID/GID `10001`. Не используйте `docker compose down -v`, если нужно сохранить данные. Конфигурация содержит пароль MQTT открытым текстом с ограниченными правами файловой системы; ответы API его скрывают.

Используйте журналы и счётчики хранилища на панели, а также:

```sh
docker compose logs --tail 100 hub
docker compose restart hub
```

Исправное состояние службы означает, что веб-сервер отвечает; состояние облака и MQTT проверяйте отдельно. Полный диск, медленное хранилище или заполненные очереди могут привести к пропускам записей, хотя пересылка продолжается. Количество отброшенных образцов смотрите в счётчиках хранилища.

Если данные не поступают, проверьте IP и порт назначения, сопоставление Docker, DHCP, список разрешённых серийных номеров и фактический перезапуск логгера. Само рукопожатие не является отчётом измерения. Если поля не декодируются, проверьте код профиля, длину, временные метки и HEX. Старые образцы не делают логгер актуальным. Если график пуст, проверьте диапазон и версию профиля. Если ESP32 недоступен, проверьте его точку доступа настройки, канал, вывод USB и питание.

Держите HTTP-интерфейсы Hub и Companion в доверенной LAN или VPN. Для удалённого доступа к Hub используйте обратный HTTPS-прокси с `HUB_COOKIE_SECURE=1`. Не открывайте неаутентифицированный приёмник V5 TCP публичному Интернету. Проверки серийного номера и IP — средства контроля LAN, а не надёжная аутентификация устройства.
