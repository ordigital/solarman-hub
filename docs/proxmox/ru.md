## Автоматическая установка VM

Выполните эту команду как **root в Shell узла Proxmox**, а не внутри VM. Мастер проведёт вас по шагам. Перед подтверждением проверьте сводку.

```sh
bash -c "$(wget -qLO - https://raw.githubusercontent.com/ordigital/solarman-hub/main/scripts/proxmox-vm.sh)"
```

Введите адрес IPv4 с маской (например `192.168.1.50/24` или `192.168.1.50/255.255.255.0`) либо оставьте поле пустым для DHCP. Шлюз и DNS запрашиваются только для статического адреса.

Мастер спросит свободный ID VM, имя, хранилище диска, хранилище типа каталог для Cloud-Init snippets, сетевой мост/VLAN, DHCP или статический IPv4 (адрес/префикс, шлюз и DNS), ресурсы, необязательный файл открытого SSH-ключа и пароль вебпанели не короче 8 символов. По умолчанию: Debian 13, 2 vCPU, 2 ГБ RAM и диск 20 ГБ. Он проверит SHA-512 официального образа и установит Docker и существующий проект Compose в новой VM. При необходимости добавит тип содержимого snippets в хранилище, сохранив остальные типы. Существующие VM не изменяются.

Установка может занять несколько минут. Затем откройте показанный адрес `http://VM_IP:8080` и введите выбранный пароль. Logger, профиль, облако и MQTT настроите в панели; скрипт не меняет logger. Для DHCP зарезервируйте адрес VM; для статического адреса выберите свободный IP вне диапазона DHCP. Данные консоли и команда получения токена восстановления сохраняются на хосте в `/root/solarman-hub-VMID-access.txt`, доступном только root. SSH принимает ключи, а не пароли. Через 15 минут ожидание заканчивается, но VM продолжает работать, а установка повторяется каждую минуту. Диагностика: `qm terminal VMID`, затем в Debian `journalctl -u solarman-hub-install`.

Сохраняйте Cloud-Init snippet вместе с резервной копией VM. Его путь указан в файле доступа; он содержит хеши паролей и, при наличии, открытый ключ. Перед миграцией или восстановлением файл должен быть доступен на целевом узле. Скрипт поддерживает Proxmox VE 8/9 на amd64, мосты Linux и хранилище типа каталог для snippets. Конфигурация проверяется автоматическими тестами, но создание VM на настоящем хосте Proxmox ещё не проверено. Перед запуском можно посмотреть [код скрипта](../../scripts/proxmox-vm.sh).

## Установка вручную

Это руководство поможет установить Solarman Hub в виртуальной машине **Debian 13 (Trixie), amd64** на Proxmox. Создайте VM в веб-интерфейсе Proxmox, а все приведённые команды выполняйте **внутри Debian**.

## 1. Создайте VM

1. Скачайте [официальный ISO Debian netinst amd64](https://www.debian.org/distrib/netinst). В Proxmox выберите узел → хранилище с поддержкой ISO → **ISO Images → Upload**.
2. Нажмите **Create VM**, назовите её `solarman-hub` и выберите загруженный ISO в **OS**. Начните с **2 vCPU, 2048 MB RAM и диска 20 GB**; это рекомендуемые ресурсы, а не измеренные минимумы. Выберите виртуальный диск в резервируемом хранилище. Более длинная история требует больше места.
3. В **Network** выберите **VirtIO** и существующий мост LAN, обычно `vmbr0`. Используйте ту же доступную LAN/VLAN, что и логгер; имя моста и VLAN могут отличаться на разных хостах.
4. Завершите создание, запустите VM и откройте **Console**. Установите Debian без графической среды. Выберите стандартные системные утилиты; сервер SSH необязателен. При установке задайте пароль root для использования консоли root ниже.
5. После установки отсоедините ISO и загрузитесь с виртуального диска. В VM → **Options** включите **Start at boot** и **QEMU Guest Agent**. После включения агента выключите и запустите VM, чтобы его виртуальный канал стал доступен; пакет агента будет установлен на следующем шаге.
6. Зарезервируйте адрес VM в настройках DHCP маршрутизатора. Узнайте текущий адрес командой `hostname -I` в Debian. Используйте его везде, где руководство указывает `VM_IP`. Он отличается от адресов управления Proxmox и логгера.

Проект рекомендует обычную VM для предсказуемой работы Docker и резервного копирования и восстановления всей VM. Docker в LXC требует дополнительной настройки хоста и контейнера; это не описанный здесь путь для начинающих. См. [официальную документацию контейнеров Proxmox](https://github.com/proxmox/pve-docs/blob/master/pct.adoc).

## 2. Установите Docker в Debian

Войдите как **root** в консоли VM Debian. В новой установке Debian 13 выполните:

```sh
apt update
apt install -y docker.io docker-cli docker-compose docker-buildx git ca-certificates qemu-guest-agent curl
systemctl enable --now docker
systemctl start qemu-guest-agent
docker compose version
docker buildx version
```

Последние команды должны показать версии Compose **v2** и Buildx. Это [пакеты Docker Debian 13](https://packages.debian.org/trixie/docker.io), включая [Compose v2](https://packages.debian.org/trixie/docker-compose) и [Buildx](https://packages.debian.org/trixie/docker-buildx); дополнительный скрипт установки не нужен. Не смешивайте их с пакетами Docker CE. Если Docker CE уже установлен, сохраните его и следуйте [официальным инструкциям для Debian](https://docs.docker.com/engine/install/debian/) вместо установки этих пакетов. Debian 12 имеет другие версии пакетов; этот рецепт предназначен для Debian 13.

## 3. Скачайте и запустите Hub

```sh
git clone https://github.com/ordigital/solarman-hub.git /opt/solarman-hub
cd /opt/solarman-hub
docker compose up -d --build --wait --wait-timeout 120
docker compose ps
docker compose exec hub solarman-hub token --data-dir /data
```

Первая сборка загружает зависимости и может занять несколько минут. Дождитесь запуска `hub`; его состояние должно стать `healthy`. Последняя команда показывает токен администратора. Храните его в тайне. Последующие команды выполняйте в том же каталоге, чтобы Compose нашёл тот же проект и том данных. Токен не меняется после перезапуска или обновления, пока сохраняется том данных.

## 4. Первое подключение и сеть

Откройте **`http://VM_IP:8080`** на компьютере в LAN и войдите с токеном. Добавьте числовой **серийный номер логгера**, выберите совместимый профиль, сохраните и примените. Затем установите удалённый TCP-адрес логгера на **`VM_IP:10000`**. Сначала сохраните исходные настройки серверов. Поведение A/B зависит от прошивки, а после изменения может потребоваться перезапуск; если отчёты не поступают, обратитесь к руководству.

| Соединение | Назначение |
|---|---|
| Логгер → Hub | IP VM, TCP `10000` |
| Браузер → панель | IP VM, TCP `8080` |
| Hub → облако | Настроенные хост и порт облака, по умолчанию `access3.solarmanpv.com:10000` |
| Hub → MQTT | Хост/порт существующего брокера; обычно `1883` или TLS-порт брокера |

Для установки и пересылки в облако VM также нужны работающий DNS, правильные часы и доступ к Интернету. MQTT требует отдельного брокера, например уже используемого Home Assistant; этот файл Compose не создаёт брокер. Включите интеграцию MQTT в HA и настройте тот же брокер в Hub.

Если включён межсетевой экран Proxmox, гостевой системы или маршрутизатора, разрешите соответствующий трафик от логгера и вашей управляющей LAN. Опубликованные Docker порты могут обходить правила UFW гостевой системы; примените ограничения на границе Proxmox/маршрутизатора или с помощью документированного механизма межсетевого экрана Docker. Не перенаправляйте порты Hub из Интернета. При описанном мостовом подключении LAN перенаправление портов хоста Proxmox не нужно. Используйте IP VM, а не частный Docker IP контейнера.

Чтобы сохранить альтернативные опубликованные порты после обновлений, создайте `/opt/solarman-hub/.env` перед запуском Hub:

```dotenv
HUB_WEB_PORT=18080
HUB_LOGGER_PORT=18899
```

Затем повторно выполните `docker compose up -d --wait --wait-timeout 120` и используйте `http://VM_IP:18080` и адрес логгера `VM_IP:18899`. Оставьте стандартные настройки прослушивания панели: эти переменные меняют порты, открытые Docker. Храните `.env` конфиденциально.

## 5. Проверка и устранение неполадок

Из `/opt/solarman-hub` внутри VM:

```sh
docker compose ps
curl --fail http://127.0.0.1:8080/health
docker compose logs --tail 100 hub
```

Если опубликованный веб-порт изменён, замените `8080`. Исправная HTTP-точка подтверждает работу службы, а не подключение логгера. Отдельно проверяйте в панели подключение логгера, последнее измерение, облако и MQTT. Измерения появятся, когда разрешённый логгер отправит совместимый отчёт. Храните сырые журналы и экспорты конфиденциально; они могут содержать идентификаторы устройств.

Если `docker compose` отсутствует, проверьте, что система — Debian 13 и что `docker-cli` и `docker-compose` успешно установлены. Если `hub` завершил работу, проверьте его журналы перед запросом токена. Если браузер не подключается, проверьте текущий IP VM, мост/VLAN, межсетевой экран и опубликованный порт. Зарезервируйте адрес, прежде чем направлять на него логгер.

## 6. Резервное копирование, обновление и восстановление

Именованный том Compose `hub-data`, смонтированный в `/data`, хранит токены, настройки, профили и историю в каталоге данных Docker этой VM. Пересборка контейнера сохраняет его. **Никогда не запускайте `docker compose down -v` и не удаляйте этот том, если хотите сохранить данные.** Не размещайте его во временной файловой системе и не исключайте его виртуальный диск из резервного копирования.

Для простой согласованной копии выберите VM → **Backup → Backup now**, отдельное хранилище копий и режим **Stop**. Это ненадолго остановит VM и сбор данных; убедитесь, что затем она работает. Запланируйте регулярные копии VM в Proxmox и проверьте восстановление. Сам снимок не является резервной копией. Копии содержат учётные данные, поэтому ограничьте доступ. См. [документацию Proxmox по копированию и восстановлению](https://github.com/proxmox/pve-docs/blob/master/vzdump.adoc).

Перед обновлением создайте копию. Затем внутри VM:

```sh
cd /opt/solarman-hub
git pull --ff-only
docker compose build --pull hub
docker compose up -d --wait --wait-timeout 120
docker compose ps
```

Это обновляет исходники и пересобирает локально установленный образ; этот способ не предполагает опубликованного образа Hub. Замена контейнера ненадолго прерывает пересылку. Не меняйте имя или каталог проекта Compose и не удаляйте том во время обновления. Обновления безопасности Debian/Docker управляются отдельно через APT.

Для восстановления выключите повреждённую VM и восстановите выбранную полную копию VM через Proxmox. При запуске восстановленной копии оставьте исходную VM выключенной, чтобы не конфликтовали IP-адреса, сеансы логгера и ID клиентов MQTT. Проверьте адрес LAN, состояние службы и последний полученный образец. Данные после создания копии теряются; отчёты, локально подтверждённые во время сбоя, автоматически в облако не добавляются.

## 7. Необязательная передача USB для ESP32

Обычная работа Hub не требует ESP32 или USB. Для необязательного инструмента прошивки подключите плату к хосту Proxmox и выберите VM → **Hardware → Add → USB Device**. Выберите эту плату и передайте её; при необходимости перезапустите VM. В Debian проверьте фактический путь устройства:

```sh
ls -l /dev/serial/by-id/
```

Затем следуйте **ESP32 / Прошивка** в панели Hub или [руководству пользователя](../../src/solarman_hub/guides/ru.md). USB, подключённый только к компьютеру с панелью, недоступен для VM. Сам веб-контейнер Hub не получает привилегий USB; прошивку выполняет отдельный одноразовый инструмент Compose. Заводская прошивка может сбросить настройки платы.
